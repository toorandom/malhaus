REST API

Submit files and URLs for automated malware analysis. Results appear in the web UI alongside browser submissions. Obtain an API key from the admin dashboard.

Authentication

Pass your API key as a bearer token in the X-Api-Key header on every request:

X-Api-Key: mh_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Keys are issued by the admin and may carry a per-hour rate limit and an optional expiry date. Revoked or expired keys receive a 401 Unauthorized response.

Python examples

All examples use the requests library. Install with pip install requests.

import time
import requests

BASE_URL = "https://your-malhaus-instance.example.com"
API_KEY  = "mh_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"

HEADERS = {"X-Api-Key": API_KEY}


# ── 1. Analyze a file ─────────────────────────────────────────────────────────
with open("/path/to/suspicious.exe", "rb") as fh:
    resp = requests.post(
        f"{BASE_URL}/api/v1/analyze",
        headers=HEADERS,
        files={"file": ("suspicious.exe", fh, "application/octet-stream")},
    )
resp.raise_for_status()
job_id = resp.json()["job_id"]
print("Submitted. job_id =", job_id)


# ── 2. Analyze a file with Ghidra decompilation enabled ───────────────────────
#  Ghidra analysis is deeper but may take several minutes (it is Java after all).
with open("/path/to/binary.exe", "rb") as fh:
    resp = requests.post(
        f"{BASE_URL}/api/v1/analyze",
        headers=HEADERS,
        files={"file": ("binary.exe", fh, "application/octet-stream")},
        data={"use_ghidra": "1"},
    )
job_id = resp.json()["job_id"]


# ── 3. Submit a URL ───────────────────────────────────────────────────────────
resp = requests.post(
    f"{BASE_URL}/api/v1/analyze",
    headers=HEADERS,
    data={"url": "https://example.com/suspicious-payload.ps1"},
)
job_id = resp.json()["job_id"]


# ── 4. Submit an encrypted ZIP or 7z ─────────────────────────────────────────
#  Common malware delivery: password-protected archives. Pass the password via
#  the archive_password field so malhaus can extract and analyse the contents.
with open("/path/to/sample.zip", "rb") as fh:
    resp = requests.post(
        f"{BASE_URL}/api/v1/analyze",
        headers=HEADERS,
        files={"file": ("sample.zip", fh, "application/zip")},
        data={"archive_password": "infected"},
    )
job_id = resp.json()["job_id"]


# ── 5. Poll for results ───────────────────────────────────────────────────────
#  Jobs are asynchronous. Poll until status == "done" or "error".
#  Typical analysis takes 10–60 s; Ghidra jobs can take several minutes.
while True:
    poll = requests.get(
        f"{BASE_URL}/api/v1/jobs/{job_id}",
        headers=HEADERS,
    )
    poll.raise_for_status()
    data = poll.json()
    status = data.get("status")
    print(f"  status: {status}")
    if status in ("done", "error"):
        break
    time.sleep(5)


# ── 6. Print verdict fields ───────────────────────────────────────────────────
if status == "done":
    result = data["result"]
    print("risk_level  :", result.get("risk_level"))    # benign / suspicious / likely_malware
    print("confidence  :", result.get("confidence"))    # high / medium / low
    print("top_reasons :", result.get("top_reasons"))   # list[str]
    print("iocs        :", result.get("iocs"))          # dict of extracted indicators
    print("tools_used  :", result.get("tools_used"))    # list[str]
else:
    print("Analysis failed:", data.get("error"))

Endpoints

Method Path Description
POST /api/v1/analyze Submit a file or URL for analysis. Returns {"job_id": "..."} immediately. Body can be multipart/form-data (file upload) or application/x-www-form-urlencoded (URL submission). Optional fields: use_ghidra=1, archive_password.
GET /api/v1/jobs/<job_id> Poll job status. Returns a JSON object with status (pending / running / done / error), and on completion a result dict or error string.

Response fields

  • risk_level benign · suspicious · likely_malware — overall verdict from the LLM verdict loop.
  • confidence high · medium · low — how confident the model is in the verdict.
  • top_reasons List of strings explaining the verdict — the most significant evidence items.
  • iocs Dict of extracted indicators: IPs, domains, URLs, registry keys, file paths, mutexes, etc.
  • tools_used List of static analysis tools that ran (e.g. objdump, olevba, ghidra).
  • sha256 SHA-256 hash of the submitted file. Results are cached by hash — resubmitting an identical file returns instantly.
  • score Deterministic heuristic score 0–100 computed before the LLM pass (entropy, IOC hits, import names, etc.).
